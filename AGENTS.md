# AGENTS.md

`Ammini` (package/crate `ammini`; the on-disk paths and eframe storage key keep the app's former `min-mpv`/`min_mpv_state` names so existing sessions, caches and saves keep working) is a Rust/egui desktop video player (`eframe` + `egui-sharkplayer`/libmpv) with a Telegram sidebar. The README covers the local-file player, the Telegram client, the proxy/cache, and shortcuts; the state machines and threading model are documented here.

## Build & run
- Rust 1.92+ (edition 2024). libmpv is required (`brew install mpv` on macOS; `build.rs` adds `/opt/homebrew/lib`/`/usr/local/lib` automatically).
- Credentials `TELEGRAM_API_ID`/`TELEGRAM_API_HASH` resolve in this order: the live environment, then a `.env` (loaded by `dotenvy` at startup), then the values **baked into the binary at build time** — `build.rs` parses `.env` and re-exports the keys via `cargo:rustc-env`, and `config.rs` falls back to `option_env!`. So a built binary runs with no `.env` next to it (it still needs libmpv at runtime), while CI (no `.env`) must provide the real environment or the build bakes nothing and startup fails as before. `build.rs` emits `cargo:rerun-if-changed=.env` because `.env` is gitignored and cargo would not otherwise notice edits to it. `.env.example` is the tracked template, and `main.rs` points users at it when credentials are missing.
- Run with `cargo run`. The `glow` renderer is required (video renders through OpenGL) — do not change it.
- Logs use `tracing`; default filter is `ammini=debug`, override with `RUST_LOG`.
- App icon: `assets/ammini-icon.png` (512², cropped to the blue squircle from `assets/ammini-logo.png`) is embedded with `include_bytes!` and set as the window icon in `main.rs`; `assets/Ammini.icns` is the same artwork for macOS bundling. Regenerate both from the logo with ImageMagick + `iconutil` if the artwork changes.
- macOS app bundle: `scripts/bundle-macos.sh` produces `dist/Ammini.app` + `dist/Ammini-<version>.dmg` (gitignored). It copies libmpv + its whole dylib closure into `Contents/Frameworks`, rewrites install names to `@rpath` (keyed by the *referenced* basename, since Homebrew's `libfoo.N.dylib` are symlinks to `libfoo.N.x.y.dylib`), drops the build-time `/opt/homebrew/lib` rpath, and ad-hoc signs. It needs no extra tools beyond macOS's `otool`/`install_name_tool`/`codesign`/`hdiutil`.

## Architecture
- Two state machines generated by the `statig` macro (`#[state_machine(...)]`), driven by `fsm.handle(&Event)`:
  - `PlayerFsm` in `src/fsm.rs` owns the `egui_sharkplayer::PlayerState`.
  - `TelegramFsm` in `src/telegram/state_machine.rs` owns auth/chat/message UI state.
- `egui-sharkplayer` is **vendored** at `vendor/egui-sharkplayer` with two small patches: a `PlayerState::mpv() -> &libmpv2::Mpv` accessor (the crate exposes no generic property API), and fixed-width time labels in `widget.rs` (`format_time_mm_ss`/`format_time_hh_mm_ss` — seconds-only, zero-padded `MM:SS`/`HH:MM:SS`, floored so `59.999` never rolls to `60` — rendered in a cell sized to the widest `00:00`/`00:00:00` layout so the seekbar doesn't shift as the digits change; covered by the `time_format_tests` mod, run via `cargo test --manifest-path vendor/egui-sharkplayer/Cargo.toml` with `LIBRARY_PATH=/opt/homebrew/lib`). `libmpv2 = "6"` is a direct dependency that unifies with the crate's own instance. The audio and subtitle track dropdowns (`main.rs`) read the scalar `track-list/N/{type,id,title,lang,selected}` sub-properties (libmpv2 cannot read the `track-list` NODE) and switch via `set_property("aid"`/`"sid"`, …)`; a shared `refresh_tracks()` rebuilds both lists only when `track-list/count` (or empty ↔ non-empty) changes, and `track_switcher_menu` renders either dropdown. `track_label` (fsm.rs) makes the human labels. When bumping egui-sharkplayer, re-apply both patches in the vendored copy.
- The UI reads/writes FSM fields through `unsafe { &mut self.fsm.inner_mut().field }` (`player_mut()`, `status_mut()`, `data_mut()` in `main.rs`/`panel.rs`). This is a deliberate pattern — follow it, don't restructure it.
- Telegram runs on a background `std::thread` with its own tokio runtime (`telegram::start()`). UI ↔ background communicate only via two unbounded mpsc channels: `BgCommand` (UI→BG) and `UiMessage` (BG→UI); `main.rs` drains `ui_rx` with `try_recv()` once per frame.
- The real proxy is `src/telegram/proxy.rs` (NOT `src/proxy.rs`, which only builds proxied URLs via `local_url_for`). It's an axum server on `127.0.0.1:0` that reports its port via `UiMessage::ProxyReady`, serving:
  - `/url?url=<encoded>` — generic remote URL proxy with request/response header whitelists.
  - `/telegram/{msg_id}` — streams Telegram video bytes with byte-range support through a **disk-backed block cache** (`src/telegram/cache.rs`). Videos are cached as 512 KiB blocks in per-video files under the OS cache dir (`~/Library/Caches/min-mpv/telegram_cache/{chat_id}_{msg_id}.bin`); RAM holds only coverage metadata. Concurrent range requests deduplicate downloads via an in-flight set + a `watch` version counter (waiter coordination — don't switch to a raw `Notify`, it misses completions). Blocks are written whole and chunk-aligned, so no partial-range bookkeeping.
  - Coverage is persisted in an atomically-rewritten sidecar manifest (`.meta`, block bitmap), so a reopened video resumes from disk instead of re-downloading; mismatched manifests are ignored. `sweep_cache_dir` runs once at bg-thread startup (30-day age, 2 GiB budget, oldest-first). `telegram_cache_stream` prefetches the next 4 blocks (2 MiB) in background tasks while streaming; `ensure` dedups so a block is still downloaded exactly once.
  - Block downloads go through `Arc<dyn VideoSource>` (`client.rs`: `GrammersVideoSource` in production, fakes in offline tests) — don't reintroduce a raw `Option<grammers Client>`.
- The bg thread keeps `video_registry: HashMap<i32, VideoDownloadInfo>` (msg_id → document metadata) and `video_cache: HashMap<i32, BlockCache>`; both are cleared on chat switch/sign-out.
- Custom font stack in `src/fonts.rs`: Inter (variable, primary face, bundled per the macOS-style pass) + bundled NotoEmoji (Unicode 15+, covers ZWJ sequences, skin tones, flags) + bundled DejaVu Sans (symbols/dingbats/arrows), plus best-effort system script fallbacks (CJK deliberately skipped on macOS to keep startup/memory light).
- `src/style.rs` owns the macOS-style theme: per-theme (light/dark) spacing, radii, borderless widgets, accent-tinted hover/selection, `ThemePreference::System`, and palette helpers (`style::is_dark(ctx)`, `hover_fill`, `selected_fill`, `bubble_other`, `text_primary/secondary`, `avatar_fill`). Custom colors MUST come from these helpers so both modes stay correct. Chat rows (`TelegramPanel::chat_row`) are painted 60px cards; messages render as grouped bubbles in `message_list_ui` (`MessageInfo.sender_is_self` decides right/accent vs left/neutral — set by the bg thread from `self_user_id`, which is captured at sign-in or fetched via `users.getUsers(InputUserSelf)` for resumed sessions; unknown → neutral).
- Buttons use Material Design icons from `egui_material_icons` 0.7 (Material Symbols font with a `material-icons` family). Keep plain text in sync: labels are built via `fonts::icon_label(ui, ICON_X, "Label")` (`src/fonts.rs`). Icon glyphs MUST be pinned to the `material-icons` family (the `MaterialIcon` → `WidgetText`/`RichText` conversions and `icon_label`'s `LayoutJob` both do this) — never render an icon codepoint as a plain string in the Proportional chain: the primary face, Inter, claims several Material PUA codepoints (e.g. `play_arrow` U+E037) with blank glyphs, and egui resolves each char to the *first* covering face, so the icon silently disappears. `MinMpvApp::new` calls `egui_material_icons::initialize(&ctx)` AFTER `fonts::install` — install uses `set_fonts` (replaces), initialize uses `add_font` (merges), so that order is required (covered by `tests/emoji_support.rs::material_icon_font_registers_and_covers_icons`, which now asserts all 25 app icons are covered by the named family). The on-video control bar drawn by egui-sharkplayer gets its glyphs from `PlayerControlIcons` in `main.rs`, a `ControlsIconProvider` impl replacing the crate's default text symbols (`<<`, `>>`, `▶`, `🔊`…) — if you add a control there, give it a matching `ICON_*`.

## Testing
- Fast offline suite: `cargo test --lib` (unit tests in `cache.rs`/`client.rs`/`proxy.rs`/`state_machine.rs`), `cargo test --test proxy_video` (offline integration: real axum server + fake `VideoSource` + temp cache — ranges, cache hits, concurrent dedup, prefetch, failures), and `cargo test --test emoji_support`. CI (`.github/workflows/ci.yml`, macOS) runs `cargo fmt --check`, `clippy --all-targets -- -D warnings`, and those three offline suites.
- `tests/hevc_proxy.rs` is a live-Telegram integration test. It auto-skips (prints "Skipping test…") when env config, an authorized session, or an HEVC video is missing, but it panics on some real failures and can be slow (scans all dialogs/messages; tail range request has a 120s timeout). A plain `cargo test` includes it — run it deliberately with `cargo test --test hevc_proxy`; it is NOT part of CI.
- Telegram session: SQLite at `dirs::data_local_dir()/min-mpv/telegram.session` (macOS: `~/Library/Application Support/min-mpv/telegram.session`), auto-persisted. UI "Sign out" revokes the session server-side (`Client::sign_out`, best effort), deletes the session file, and wipes the `telegram_cache` dir — the next launch starts logged out.
- App state persists under eframe storage key `min_mpv_state`: recent files, playlist + current track, volume, per-file resume positions (local files only; `resume` is recorded in the `playing` state, throttled, and applied via `resume_pending` on the `loading`→`playing` transition), and `recent_telegram` (PeerRef + chat name + msg_id + display name, recorded when `UiMessage::VideoReady` arrives, capped at 10, `record_recent_telegram`; the PeerRef carries the access hash, so it must be serialized as-is — grammers-session is built with its `serde` feature for this). The Recent menu replays those via `BgCommand::PlayTelegramVideo`, which refetches the message with `client::fetch_video_info` (`get_messages_by_id` + the same `extract_video` path) because the registry is cleared on chat switch/sign-out — never assume the registry still holds a replayed video, and never rebuild the peer from a bare dialog id (channels reject default-authority refs). New `PersistentState` fields MUST use `#[serde(default)]`, otherwise old saves fail to parse and reset to defaults.

## Gotchas
- Shortcuts are documented in the README (`Cmd+U` URL dialog, `Cmd+T` Telegram panel, `Space`/`F`/`M`/`+`/`-` transport fallbacks that only fire when the video surface is unfocused — the SharkPlayer widget owns those keys while focused).
- `egui_material_icons` is pinned to the app's egui version: 0.7 ↔ egui 0.35 (latest 0.8 requires egui 0.36, and egui crates can't mix versions in one graph). Do not bump eframe/egui without bumping this crate to the matching release.
- `cargo build` prints a future-incompat warning about `proc-macro-error2` (transitive dep of `statig_macro`/`statig`: `pub use proc_macro` at lib.rs:494, Rust issue #127909). It is harmless and deliberately ignored — the proc-macro-error2 repo is archived, `statig` main still pins 2.0.1, and there is no newer fixed version. Don't try to "fix" it by bumping/patching deps; revisit only if a future Rust promotes E0365 to a hard error.
- `egui` panics at startup if any registered font fails to parse — only add fonts that are guaranteed to exist (see note in `src/fonts.rs`).
