# AGENTS.md

`Ammini` (package/crate `ammini`; the on-disk paths and eframe storage key keep the app's former `min-mpv`/`min_mpv_state` names so existing sessions, caches and saves keep working) is a Rust/egui desktop video player (`eframe` + `egui-sharkplayer`/libmpv) with a Telegram sidebar. The README covers the local-file player, the Telegram client, the proxy/cache, and shortcuts; the state machines and threading model are documented here.

## Build & run
- Rust 1.92+ (edition 2024). libmpv is required (`brew install mpv` on macOS; `build.rs` adds `/opt/homebrew/lib`/`/usr/local/lib` automatically).
- Credentials `TELEGRAM_API_ID`/`TELEGRAM_API_HASH` resolve in this order: the live environment, then a `.env` (loaded by `dotenvy` at startup), then the values **baked into the binary at build time** — `build.rs` parses `.env` and re-exports the keys via `cargo:rustc-env`, and `config.rs` falls back to `option_env!`. So a built binary runs with no `.env` next to it (it still needs libmpv at runtime), while CI (no `.env`) must provide the real environment or the build bakes nothing and startup fails as before. `build.rs` emits `cargo:rerun-if-changed=.env` because `.env` is gitignored and cargo would not otherwise notice edits to it. `.env.example` is the tracked template, and `main.rs` points users at it when credentials are missing.
- Run with `cargo run`. The `glow` renderer is required (video renders through OpenGL) — do not change it.
- Logs use `tracing`; default filter is `ammini=debug`, override with `RUST_LOG`.
- App icon: `assets/ammini-icon.png` (512², cropped to the blue squircle from `assets/ammini-logo.png`) is embedded with `include_bytes!` and set as the window icon in `main.rs`; `assets/Ammini.icns` is the same artwork for macOS bundling. Regenerate both from the logo with ImageMagick + `iconutil` if the artwork changes.
- macOS app bundle: `scripts/bundle-macos.sh` produces `dist/Ammini.app` + `dist/Ammini-<version>.dmg` (gitignored). It copies libmpv + its whole dylib closure into `Contents/Frameworks`, rewrites install names to `@rpath` (keyed by the *referenced* basename, since Homebrew's `libfoo.N.dylib` are symlinks to `libfoo.N.x.y.dylib`), drops the build-time `/opt/homebrew/lib` rpath, and ad-hoc signs. It needs no extra tools beyond macOS's `otool`/`install_name_tool`/`codesign`/`hdiutil`. The only env var it reads is `MIN_MACOS` (floor *check* — the real `LSMinimumSystemVersion` is auto-detected from the bundled dylibs' deployment targets).
- Releases: conventional commits drive `release-plz` (`.github/workflows/release-plz.yml` on push to main; `release-plz.toml` sets `publish = false`, `git_only = true` so versions come from git tags, and `release_always = false` so a release is only cut when the "chore(release)" PR merges). Merging that PR tags `v<version>` + creates the GitHub Release with the generated `CHANGELOG.md`. `build-macos.yml` (tags `v*` + `workflow_dispatch`) bundles the DMG on a **macos-15** runner (arm64 — the DMG is Apple-silicon-only; the runner's OS sets the floor) and uploads the DMG + full bundler log as run artifacts, attaching the DMG to the Release on tag refs. Tags/releases created by GITHUB_TOKEN (release-plz) do NOT trigger other workflows, so dispatch the build manually for release-plz-made tags: `gh workflow run build-macos.yml --ref v<version>`. The four baked credentials (`TELEGRAM_API_ID`/`TELEGRAM_API_HASH`/`SENTRY_DSN`/`SENTRY_OTLP_URL`) are repo secrets, set from `.env` via `gh secret set`.

## Architecture
- Two state machines generated by the `statig` macro (`#[state_machine(...)]`), driven by `fsm.handle(&Event)`:
  - `PlayerFsm` in `src/fsm.rs` owns the `egui_sharkplayer::PlayerState`.
  - `TelegramFsm` in `src/telegram/state_machine.rs` owns auth/chat/message UI state.
- `egui-sharkplayer` is **vendored** at `vendor/egui-sharkplayer` with five small patches: a `PlayerState::mpv() -> &libmpv2::Mpv` accessor (the crate exposes no generic property API), fixed-width time labels in `widget.rs` (`format_time_mm_ss`/`format_time_hh_mm_ss` — seconds-only, zero-padded `MM:SS`/`HH:MM:SS`, floored so `59.999` never rolls to `60` — rendered in a cell sized to the widest `00:00`/`00:00:00` layout so the seekbar doesn't shift as the digits change; covered by the `time_format_tests` mod, run via `cargo test --manifest-path vendor/egui-sharkplayer/Cargo.toml` with `LIBRARY_PATH=/opt/homebrew/lib`), a `seek_callback(Option<Rc<dyn Fn(bool, f64)>>)` invoked after every arrow/J/L/skip-button seek (`true` = forward, plus the widget-side predicted target position) so the app can time seek latency, and a custom-painted seekbar with `cache_overlay(Vec<(f64, f64)>, Color32)` — the seekbar no longer uses `egui::Slider`; `widget.rs::seekbar` paints rail → cached spans (a lighter shade, under the played fill so the full extent shows even behind the playhead) → played fill → handle, mirrors egui's slider geometry (rail centered in an interact-sized allocation, handle radius = height/2.5, position shrunk by the handle), and re-implements click/drag seek + hover tooltip identically (only the slider's internal keyboard-focus nav is dropped — the app never used it). `backend.rs::seek_relative` also seeks by **keyframe** (the stock crate used `relative+exact`, which decodes up to the target frame on every arrow/skip press and feels laggy over the streamed Telegram proxy) — don't re-add `exact`. `UiState.last_time_pos` keeps the last valid playback position and is the fallback when mpv reports `time-pos` unavailable mid-seek, so the time label never flashes a bogus `00:00` after a keyframe seek (reset to 0 while a new file is loading, detected via `duration` going unavailable). `libmpv2 = "6"` is a direct dependency that unifies with the crate's own instance. The audio and subtitle track dropdowns (`main.rs`) read the scalar `track-list/N/{type,id,title,lang,selected}` sub-properties (libmpv2 cannot read the `track-list` NODE) and switch via `set_property("aid"`/`"sid"`, …)`; a shared `refresh_tracks()` rebuilds both lists only when `track-list/count` (or empty ↔ non-empty) changes, and `track_switcher_menu` renders either dropdown. `track_label` (fsm.rs) makes the human labels. When bumping egui-sharkplayer, re-apply all five patches in the vendored copy. The fifth: `SharkPlayer::player_focus_id(ui)` exposes the internal focusable player surface id (keyboard focus lands there, NOT on the response `Widget::ui` returns — use it for any `has_focus` checks in the host), and `handle_keybinds` sets `memory.set_focus_lock_filter` with `horizontal_arrows`/`vertical_arrows` while the player surface is focused (egui 0.35 maps bare arrow keys to focus navigation, which otherwise steals focus off the video on the first arrow press and kills arrow seek until the next click; same pattern as egui's own `Slider`). `handle_keybinds` also returns early while Command is held, so Cmd/Ctrl+←/→ reaches the host's prev/next handling instead of also seeking the current video, and `action_seek_back` clamps with `.max(0.)` (it used `.min(0.)`, which collapsed the played fill to 0 for a frame on every rewind — briefly uncovering the whole cache shade).
- The UI reads/writes FSM fields through `unsafe { &mut self.fsm.inner_mut().field }` (`player_mut()`, `status_mut()`, `data_mut()` in `main.rs`/`panel.rs`). This is a deliberate pattern — follow it, don't restructure it.
- Telegram runs on a background `std::thread` with its own tokio runtime (`telegram::start()`). UI ↔ background communicate only via two unbounded mpsc channels: `BgCommand` (UI→BG) and `UiMessage` (BG→UI); `main.rs` drains `ui_rx` with `try_recv()` once per frame. A separate `telegram/updates.rs` task drives the sender pool's update stream (`Client::stream_updates`, `catch_up: true`) and forwards new messages as `UiMessage::MessageReceived` — edits/deletions/callbacks/raw are intentionally ignored. `client.rs::connect` hands back the pool's `updates` receiver for it, and the listener reads `self_user_id`/`selected_chat_id` through `Arc<AtomicI64>`s (`0` = unset) shared with the command loop; it registers a live video into `video_registry` only when the message's chat is the selected one (the registry holds only the current chat). The FSM appends via `TelegramData::receive_message` (`push_message` dedupes by id, oldest-first) and bumps the chat-list preview/order.
- `src/telemetry.rs` is a typed event emitter (`TelemetryEvent` + `telemetry::emit`) feeding Sentry through two channels on a dedicated `ammini-telemetry` thread (own tokio runtime, mirroring `telegram::start()`): OTLP logs via `opentelemetry`/`opentelemetry-sdk`/`opentelemetry-otlp` 0.33 (features `logs, http-proto, reqwest-client`, no default features — use `reqwest-client`, NOT `hyper-client`: opentelemetry-http's hyper client has no TLS backend) to `SENTRY_OTLP_URL + /v1/logs` (the exporter only appends `/v1/logs` to bare base URLs — the full path is built in `build_logger`), authenticated with `x-sentry-auth: sentry sentry_key=<dsn public key>` (public key = DSN up to the first `@`, parsed by `dsn_public_key`; Sentry rejects the full DSN) — records are built through `provider.logger().create_log_record()`, batched (5 s / 64 records) and exported via `LogBatch::new(&refs)` with retry/backoff, dropped on close; and native metrics via the `sentry` crate 0.49 (`default-features = false`, `metrics, transport, reqwest, backtrace, contexts`) — Sentry does not ingest OTLP metrics, so counters/distributions (`telegram.download.speed`, `cache.hits/misses`, `videos.played`, `playback.errors`, `player.seek.latency`) go through `sentry::metrics`, SDK default integrations disabled so panics/errors aren't double-captured. Credentials resolve env → `.env` → baked (build.rs now also bakes `SENTRY_DSN`/`SENTRY_OTLP_URL`; an explicitly empty env var opts out of a baked value); missing/empty/malformed ⇒ telemetry disabled, `emit` no-ops. Emit sites: `load_media` (fsm.rs, playback start/fail — source derived from path shape), the Telegram `VideoReady`/sign-in/sign-out sites in `telegram/mod.rs` (`TelegramVideoPlayed` carries the display name, size and `video_meta(document)` — duration, resolution, mime — via `video_display_name`/`video_meta`), the `UiMessage::Error`/`AuthError`/`VideoError` drain in `main.rs` (central — don't scatter bg-loop emits), `AppStarted` + panic hook in `main()`, Recent-menu picks and audio-track switches in `top_bar` (recent files emit basenames only). User identity (by explicit request): the phone-code / 2FA sign-in handlers and the resumed-session path in `telegram/mod.rs` emit `TelegramUserIdentified` (display name + phone, via `client::user_identity`/`self_user_identity`), which sets the Sentry scope user (username) on the telemetry thread and logs one `telegram.user_identified` record; sign-out clears the scope user. Seek latency: the widget's `seek_callback` installs a `SeekTracker` (target + tolerance `SEEK_RESUME_TOLERANCE`, `SEEK_PENDING_TIMEOUT` drops seeks that never resume, e.g. paused) into `AmminiApp.pending_seek` (Arc<Mutex> because the callback outlives its frame; `poll_seek` drains it once per frame into `player.seek.latency` ms). Telegram stream metrics are aggregated per-window in `telegram_cache_stream` (2 s windows) so per-block emits don't flood the channel. `TelemetryGuard` (held in `main`) flushes on exit. Test-only decoding tricks: `add_attribute` needs explicit `Value → AnyValue` conversion (no `From<Value>` in the api crate; u64 attrs must cast to i64), and `set_event_name` takes `&'static str` literals only. Offline unit tests live in the module (mapping, batching with a fake `LogExporter`, `SeekTracker`, config precedence); an env-gated smoke test sends one real record — run deliberately, not in CI.
- The real proxy is `src/telegram/proxy.rs` (NOT `src/proxy.rs`, which only builds proxied URLs via `local_url_for`). It's an axum server on `127.0.0.1:0` that reports its port via `UiMessage::ProxyReady`, serving:
  - `/url?url=<encoded>` — generic remote URL proxy with request/response header whitelists.
  - `/telegram/{msg_id}` — streams Telegram video bytes with byte-range support through a **disk-backed block cache** (`src/telegram/cache.rs`). Videos are cached as 512 KiB blocks in per-video files under the OS cache dir (`~/Library/Caches/min-mpv/telegram_cache/{chat_id}_{msg_id}.bin`); RAM holds only coverage metadata. Concurrent range requests deduplicate downloads via an in-flight set + a `watch` version counter (waiter coordination — don't switch to a raw `Notify`, it misses completions). Blocks are written whole and chunk-aligned, so no partial-range bookkeeping.
  - Coverage is persisted in an atomically-rewritten sidecar manifest (`.meta`, block bitmap), so a reopened video resumes from disk instead of re-downloading; mismatched manifests are ignored. `sweep_cache_dir` runs once at bg-thread startup (30-day age, 2 GiB budget, oldest-first). `telegram_cache_stream` prefetches the next 4 blocks (2 MiB) in background tasks while streaming; `ensure` dedups so a block is still downloaded exactly once.
  - Block downloads go through `Arc<dyn VideoSource>` (`client.rs`: `GrammersVideoSource` in production, fakes in offline tests) — don't reintroduce a raw `Option<grammers Client>`.
- The bg thread keeps `video_registry: HashMap<i32, VideoDownloadInfo>` (msg_id → document metadata) and `video_cache: HashMap<i32, BlockCache>`; both are cleared on chat switch/sign-out. A tokio task spawned at startup ticks once per second and emits `UiMessage::CacheCoverage { msg_id, total_bytes, ranges }` for every entry in `video_cache` (usually the current video; `BlockCache::cached_byte_ranges` merges present blocks into contiguous byte ranges). `main.rs` stores these per msg_id and `AmminiApp::current_cache_spans` converts the ranges of the currently playing `/telegram/{msg_id}` URL (parsed by `telegram_url_msg_id`) into time spans via `cache::byte_ranges_to_time_spans` — a **linear byte→time approximation** (the block cache is byte-addressed with no byte↔time index), so cached coverage is accurate in bytes but approximate in time for VBR files — and shades them on the seekbar with `style::cache_bar_fill`. Do not replace the linear mapping with demuxer-cache-state: mpv's readahead is not the disk cache. `AmminiApp::telegram_load_in_progress` (FSM state `FsmState::Loading { .. }`, re-checked against the path via `telegram_url_msg_id`) drives a dimmed spinner overlay over the video while a Telegram file's initial load is in progress — painted (not a widget) so it never steals video clicks; local files are too fast to bother.
- Custom font stack in `src/fonts.rs`: Inter (variable, primary face, bundled per the macOS-style pass) + bundled NotoEmoji (Unicode 15+, covers ZWJ sequences, skin tones, flags) + bundled DejaVu Sans (symbols/dingbats/arrows), plus best-effort system script fallbacks (CJK deliberately skipped on macOS to keep startup/memory light).
- `src/style.rs` owns the macOS-style theme: per-theme (light/dark) spacing, radii, borderless widgets, accent-tinted hover/selection, `ThemePreference::System`, and palette helpers (`style::is_dark(ctx)`, `hover_fill`, `selected_fill`, `cache_bar_fill`, `bubble_other`, `bubble_stroke`, `chip_fill/outline/text`, `status_ready`, `text_primary/secondary`, `avatar_fill`). Custom colors MUST come from these helpers so both modes stay correct. Chat rows (`TelegramPanel::chat_row`) are painted 60px cards; messages render as grouped bubbles in `message_list_ui` (`MessageInfo.sender_is_self` decides right/accent vs left/neutral — set by the bg thread from `self_user_id`, which is captured at sign-in or fetched via `users.getUsers(InputUserSelf)` for resumed sessions; unknown → neutral). Video messages render as a media card (`panel.rs::video_card`): header (size · duration + Ready/Playing/Preparing status + compact Play pill), derived title/subtitle, chips (season/episode `S02E01` first, then quality/encoding), and the original file name. The title/chips come from `src/telegram/media_meta.rs` (`MediaMeta::parse`, a dependency-free filename scan for `SxxExx`/year/resolution/source/codec/audio/etc.), precomputed in `client.rs::map_message` and carried on `MessageInfo.media` so the UI never parses per frame; `format_bytes`/`format_duration` live there too. A card with a caption skips the derived title/subtitle to avoid repeating the file name, and a card with no caption still shows the file name — a video bubble is never blank. `video_card` shrinks the Play pill to icon-only below 220px so it fits the narrow sidebar. The bubble `Frame` content is wrapped in `ui.vertical` on purpose: a `Frame`'s content `Ui` inherits the bubble's horizontal layout, so without it every row after the first collapses into a zero-width column against the edge and wraps one character per line.
- `src/display_sleep.rs` keeps the display awake while media plays via the `keepawake` crate (macOS: IOKit `NoDisplaySleep` + `NoIdleSleep` assertions, same as a real video player). egui/winit expose no screensaver control and libmpv here runs with a render context (no VO), so mpv's `stop-screensaver` is a no-op — don't "fix" this with mpv options. `AmminiApp::update_display_sleep` calls `Guard::set_playing(loaded && !paused)` once per frame; the lock is created/dropped on play ↔ pause transitions only (keepawake has no toggle), so the screen dims normally while paused.
- Buttons use Material Design icons from `egui_material_icons` 0.7 (Material Symbols font with a `material-icons` family). Keep plain text in sync: labels are built via `fonts::icon_label(ui, ICON_X, "Label")`, icon-only buttons via `fonts::icon_only`, and filled accent buttons via `fonts::icon_label_colored` (white text on the accent fill) (`src/fonts.rs`). Icon glyphs MUST be pinned to the `material-icons` family (the `MaterialIcon` → `WidgetText`/`RichText` conversions and `icon_label`'s `LayoutJob` both do this) — never render an icon codepoint as a plain string in the Proportional chain: the primary face, Inter, claims several Material PUA codepoints (e.g. `play_arrow` U+E037) with blank glyphs, and egui resolves each char to the *first* covering face, so the icon silently disappears. `AmminiApp::new` calls `egui_material_icons::initialize(&ctx)` AFTER `fonts::install` — install uses `set_fonts` (replaces), initialize uses `add_font` (merges), so that order is required (covered by `tests/emoji_support.rs::material_icon_font_registers_and_covers_icons`, which now asserts all 25 app icons are covered by the named family). The on-video control bar drawn by egui-sharkplayer gets its glyphs from `PlayerControlIcons` in `main.rs`, a `ControlsIconProvider` impl replacing the crate's default text symbols (`<<`, `>>`, `▶`, `🔊`…) — if you add a control there, give it a matching `ICON_*`.

## Testing
- Fast offline suite: `cargo test --lib` (unit tests in `cache.rs`/`client.rs`/`proxy.rs`/`state_machine.rs`/`telemetry.rs`), `cargo test --test proxy_video` (offline integration: real axum server + fake `VideoSource` + temp cache — ranges, cache hits, concurrent dedup, prefetch, failures), and `cargo test --test emoji_support`. CI (`.github/workflows/ci.yml`, macOS) runs `cargo fmt --check`, `clippy --all-targets -- -D warnings`, and those three offline suites.
- Telemetry smoke test (live Sentry delivery) is env-gated inside `src/telemetry.rs`'s `live_smoke_test` — it sends one OTLP record + one metric through the real pipeline with the real `.env` credentials; run it deliberately (`cargo test --lib live_smoke_test -- --ignored`), it is NOT part of CI.
- `tests/hevc_proxy.rs` is a live-Telegram integration test. It auto-skips (prints "Skipping test…") when env config, an authorized session, or an HEVC video is missing, but it panics on some real failures and can be slow (scans all dialogs/messages; tail range request has a 120s timeout). A plain `cargo test` includes it — run it deliberately with `cargo test --test hevc_proxy`; it is NOT part of CI.
- Telegram session: SQLite at `dirs::data_local_dir()/min-mpv/telegram.session` (macOS: `~/Library/Application Support/min-mpv/telegram.session`), auto-persisted. UI "Sign out" revokes the session server-side (`Client::sign_out`, best effort), deletes the session file, and wipes the `telegram_cache` dir — the next launch starts logged out.
- App state persists under eframe storage key `min_mpv_state`: recent files, playlist + current track, volume, per-file resume positions, and `recent_telegram` (PeerRef + chat name + msg_id + display name, recorded when `UiMessage::VideoReady` arrives, capped at 10, `record_recent_telegram`; the PeerRef carries the access hash, so it must be serialized as-is — grammers-session is built with its `serde` feature for this). Resume offsets live in `PersistentState.resume` keyed by `fsm::resume_key`: local files by path, Telegram videos by `telegram:{msg_id}` (proxy URLs are session-scoped — the port changes every launch — so keying by URL would never match; this mirrors the proxy registry/cache per-message identity, so two chats sharing a msg_id collide, an accepted trade-off). `resume` is recorded in the `playing` state (throttled) and on quit via `finalize_session` (`App::save`, called on Cmd+W/Cmd+Q/close and every autosave; Cmd+W/Cmd+Q also record immediately in `handle_shortcuts` via `record_session_before_close`), and applied via `resume_pending` on the `loading`→`playing` transition. The Recent menu replays Telegram entries via `BgCommand::PlayTelegramVideo`, which refetches the message with `client::fetch_video_info` (`get_messages_by_id` + the same `extract_video` path) because the registry is cleared on chat switch/sign-out — never assume the registry still holds a replayed video, and never rebuild the peer from a bare dialog id (channels reject default-authority refs). New `PersistentState` fields MUST use `#[serde(default)]`, otherwise old saves fail to parse and reset to defaults.

## Gotchas
- Shortcuts are documented in the README (`Cmd+U` URL dialog, `Cmd+T` Telegram panel, `Space`/`F`/`M`/`+`/`-` and bare `←`/`→` (±10 s keyframe seek) transport fallbacks that only fire when the video surface is unfocused (checked via `SharkPlayer::player_focus_id`, not the widget's returned response) — the SharkPlayer widget owns those keys while focused).
- `egui_material_icons` is pinned to the app's egui version: 0.7 ↔ egui 0.35 (latest 0.8 requires egui 0.36, and egui crates can't mix versions in one graph). Do not bump eframe/egui without bumping this crate to the matching release.
- `cargo build` prints a future-incompat warning about `proc-macro-error2` (transitive dep of `statig_macro`/`statig`: `pub use proc_macro` at lib.rs:494, Rust issue #127909). It is harmless and deliberately ignored — the proc-macro-error2 repo is archived, `statig` main still pins 2.0.1, and there is no newer fixed version. Don't try to "fix" it by bumping/patching deps; revisit only if a future Rust promotes E0365 to a hard error.
- `egui` panics at startup if any registered font fails to parse — only add fonts that are guaranteed to exist (see note in `src/fonts.rs`).
